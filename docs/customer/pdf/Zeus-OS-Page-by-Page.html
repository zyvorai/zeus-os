How to get there

  • Route: /vms/:namespace/:name
  • From VMs inventory — click a row
  • Command palette — search the VM name (when indexed)

Operate from the console (UX)

  1. Open /vms/:namespace/:name from the sidebar, workspace switcher, or command palette (⌘K / Ctrl+K).
  2. Read the PageHead / deck line — confirm it matches: Full-page operations surface for one virtual machine: power, console, hardware, networking, backup panels, guest agent, ….

# Kryton repo
./scripts/deploy-remote.sh <host> <user> --quick --key

Create body (kubevirt provider)

POST /kryton/machines (Zeus or Kryton) requires a disk size. Omitting it returns disk.sizeGiB must be between 16 and 65536. The Create VM wizard sends disk.sizeGiB from the catalog defaultDiskGiB (see useCreateVmSubmit).

{
  "name": "win-lab-01",
  "image": "windows-tiny11-core",
  "project": "default",
  "compute": { "cpu": 2, "memoryMiB": 4096 },
  "disk": { "sizeGiB": 64 }
}

When Kryton’s provider is kubevirt, only images with a CDI DataSource in kryton-images create successfully (GET /kryton/status → doctor kubevirt-images).

Golden images — do not trust a one-minute “ready”

A real dockur install + Sysprep takes well over an hour. If GET /kryton/golden/{id} flips to ready in ~1 minute, treat the qcow2 as suspect: VNC of a clone often shows Windows Setup (“restarted unexpectedly”) instead of a desktop, and RDP never comes up.

Before bootstrap / create:

  1. Confirm the dockur console finished install + Sysprep (not stuck at “58% windows_setup”).
  2. Confirm outputPath qcow2 is from a FINALIZE=1 capture (Kryton build-golden-image.sh must preserve parent FINALIZE / IMAGE_ID — see Kryton docs/GOLDEN-IMAGES.md).
  3. Prefer availability: stored + a fresh sha after a long build over catalog aliases that share one path (lab saw windows-11-pro and windows-tiny11-core pointing at the same core11 qcow2).

CDI bootstrap gotchas

Symptom Cause / fix
Bootstrap / virtctl image-upload can’t reach uploadproxy Service is ClusterIP-only — port-forward or set an external uploadproxy URL
Import fails on small PVC Virtual disk can be ~80 Gi — use a ≥96 Gi PVC
IncompatibleVolumeModes on clone Golden DV was Filesystem; target expected Block (or reverse). Match volume modes on clone, or rebuild golden as Block

Day-2 (VNC + native RDP)

After create, open the VM in Zeus (VNC, native RDP NodePort, GuestKit) using Kryton’s providerRef namespace/name (zeusVm deep-link). Guest agent tooling remains GuestKit / QEMU-GA — not Kryton.

Native RDP (POST /api/v1/vms/{ns}/{name}/rdp-access/expose) needs all of:

  1. Guest listening on 3389 (finalized golden / RDP enabled — not mid-Setup).
  2. Masquerade port 3389 on the VM interface (vm_spec_has_rdp_port; Zeus Windows create merges this automatically — hand-rolled VMs must add it and restart).
  3. Service selector vm.kubevirt.io/name=<vm> (KubeVirt always labels virt-launcher pods this way). Empty endpoints + No route to host on the NodePort usually means a stale kubevirt.io/vm= selector.

Probe from the host: Service endpoints → pod IP:3389 (masquerade DNAT to 10.0.2.2) → NodePort. Guest-agent absence is common on Tiny11; use VNC to confirm desktop vs Setup.

  3. Each row shows month-to-date estimated spend, usage against the limit, a status chip, and which thresholds have already alerted this month. Unknown means no cost data has been recorded for that scope this month; it is never shown as zero and never alerts.
